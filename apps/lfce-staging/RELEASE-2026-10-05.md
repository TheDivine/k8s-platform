## Public verification and health routing follow-up

Independent TLS-validated checks confirmed all four released frontend assets
match source commit `0dc2366fd03f4de25d65a93bbd0356024eb0a619`, and protected
Settings returns `401 Unauthorized`. Public `/health` and `/readyz` instead
returned the frontend HTML 404 response. Evidence:
https://github.com/TheDivine/lfce_app/actions/runs/37243233122

The existing Traefik rules tie at 56 characters: the exact health paths and
frontend `PathPrefix(`/`)` have equal default priority. `/api` has priority59.
Traefik does not guarantee Exact precedence over Prefix at equal priorities:
https://doc.traefik.io/traefik/reference/routing-configuration/kubernetes/ingress/

Move only `/health` and `/readyz` to `Ingress/lfce-health` with explicit priority
100. Keep the original host, TLS secret, entrypoint, Exact path types and backend
service. The original Ingress retains API, frontend and ExternalDNS ownership.
No workload, credential, provider, migration or storage setting changes.
Canonical live verification must be repeated after reconciliation. Direct Argo
revision/health and authenticated operator workflow remain unverified from this
laptop because its private cluster route is unavailable.

To undo this routing adjustment, revert its Git commit; image rollback is
independent and uses the previous digests above.
